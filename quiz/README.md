# The quiz bank

`bank-<hash>.json` is every question the game can ask and the answer to each. It follows
[`/proto`](../proto) and [`/map`](../map): the root holds the source, one command writes it, and the
app that needs it carries a **committed, byte-identical copy** generated by a target, because each
app's Docker build context is its own directory and neither can read the repo root at build time.

| app | copy | refreshed by |
| --- | --- | --- |
| backend | `apps/backend/generated/quiz/<blob>`, embedded | `make quiz` |
| frontend | **none, on purpose** | — |

```bash
cd apps/frontend && npm run quiz:generate   # rewrite /quiz/bank-<hash>.json
cd apps/backend && make quiz                # → apps/backend/generated/quiz
```

The file is content-addressed — the name carries the first 8 hex of its sha256 — so a stale copy is
visible by eye rather than by symptom, and the backend's embed glob refuses a directory holding two.

## The frontend never gets a copy

This is the one thing shared here that is **not** shared with both apps, and the reason is the whole
security model: the answer is in the file. A bank served to the page is a bank anyone can fetch with
the network tab open, and every quiz would be free.

So the bank is the server's. `OpenQuiz` hands the client one question and three choices, and
**which of the three is right never leaves the server**. `AnswerQuiz` is what compares, and it is
also what starts the clock — see the backend's CLAUDE.md.

## Two halves, and why they are separate

**The derived half is about 970 questions and cannot rot.** Capitals, land borders, continents and
populations, from the same pinned Natural Earth snapshot `map/` is cut from
(`NATURAL_EARTH_TAG` in `apps/frontend/scripts/map/naturalEarth.mjs`). It is regenerated, never
corrected: a wrong answer here is a generator to fix or a pin to move, not a line to edit.

Two of those templates are worth knowing about:

- **A border is a border on the map being played**, not one in a polygon file. `scripts/quiz/
  adjacency.mjs` reads the shipped coordinates and borders blobs and calls two countries neighbours
  when two of their tiles touch on the lattice — the same edge relation the flags and the backend's
  own adjacency are built from. So "which of these borders Estonia" can be answered by looking at
  the globe, and France borders Brazil, because on this map it does.
- **A population is the one derived fact that moves**, so `mostPeople` is only built where the
  answer wins by two times over. That ordering survives a decade of either country growing.

**The hand-written half is 40 questions** in `apps/frontend/scripts/quiz/extra.json`, for what no
dataset here can answer — Yugoslavia, the stars on the US flag, how Brasília is spelled. It is a
hand-kept list and it is small on purpose. The rule at the top of that file is the important part:
**nothing that a newspaper could make wrong.** No office-holders, no populations, no current events.
A question about who the president of Egypt is would be a question this repo has to remember to
maintain, and it would not.

## Adding to it

- A new *kind* of question is a template in `apps/frontend/scripts/quiz/templates.mjs`. It must be
  derivable from the pinned data, and it must produce at least two wrong answers or it is skipped.
- A new *one-off* question is an entry in `extra.json`.
- Either way: `npm run quiz:generate`, then `make quiz`, then commit both copies.

The generator refuses to write a bank where a question has no id, a repeated id, fewer than two
wrong answers, or an answer that is also one of its own wrong ones — which is the fault a derived
bank produces quietly, when two countries share the name of a capital.

**Each question carries five wrong answers and a round shows two.** So the same question is not the
same three choices twice, and "press the second one for Estonia" is worth nothing.
