# Local full stack

`deploy/docker-compose.yaml` runs backend + frontend together using locally built Docker images, beside a postgres and a Redis. Build each app's image first (`apps/frontend`'s `npm run dBuild`, `apps/backend`'s `make dBuild`), then `cd deploy && docker compose up`.

The stack includes a **postgres**: the backend keeps the whole tile map in process and writes what changed to postgres every second. The ledger and the bonus charges each account holds go there too, the antibot keeps its evidence there in its own schema and reads and writes its bans there directly, the chat reads and writes its messages, reactions and when each account last saw it there directly, and broadcasts a write only once it is kept, the player module reads and writes profiles and stats there on every call, the seasons module keeps each season's standings and its rounds there, the rules module its schedule of rule sets, and the support module keeps what players send the operator there. The photos and videos a player attaches are the one thing kept elsewhere, in an S3 bucket, and they are off in this stack. The **Redis** carries what one module tells the others (Redis Streams, one per kind of event; see the backend's [Composite layer](../apps/backend/docs/composite-layer.md#telling-other-modules-what-happened)), and holds nothing else. See the backend's [Durability](../apps/backend/docs/durability.md) for the tradeoff and [Configuration](../apps/backend/docs/configuration.md) for the full config schema.
