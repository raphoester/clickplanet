# Shared protobuf contract

`proto/` is the **single source of truth** for the API contract — every app generates its own bindings from it (nothing here is hand-copied between apps). One package per bounded context:

- `proto/planet/v1/planet.proto` — the tile game (`ClickService`). Every answer that names tiles names their board by
  name since 2026-11-17: `GetMapResponse.board`, the stream's opening `Heartbeat.board`, `MapHistory.eras`,
  `GetReplayResponse.eras`, `GetLedgerResponse.board` and the vandal squad's `Graffiti.board` (see [Boards](boards.md)).
  Since 2026-11-18 (PR 3) also each tile's hits' era (`TileHits.era`, as two eras' tile ids collide), the board of each
  `TilesTaken` and `Fortified`, of `GetTerritories`, `GetCountrySizes` and `GetTiles` (the board in play's), and the
  rule set's `ArenaRules.board`, the board an arena's map plays. Beside it, `totals.proto` is `LedgerTotals`, the
  ledger's acts of each kind in a window, which the internal `GetLedgerTotals` answers and the gamemaster relays, and
  `history.proto` is `MapHistory`, the map every step of a window, when in the step each tile changed, each tile's hits, and the eras the window covers (`BoardEra`, each with its board's name, since 2026-11-17), which the internal
  `GetMapHistory` answers and the gamemaster relays as `GetSeasonReplay`, and which `ClickService/GetRecentMapHistory`
  answers for the last 24 hours, every 30 minutes (`TileOwner.account_id`, the account that made each change, is
  `reserved` since 2026-11-12: nothing read it once the player's video named the maker alone). `rules.proto` is `planet.v1.Rules`, a rule set
  as postgres keeps it: the wallet's values are `charges` (`ChargeRules`), what the page reads of them `GetChargeRules`.
  Until 2026-11-11 they were half of `bonuses` (`BonusRules`, field 3 `reserved` now) and the page read `GetBonusRules`;
  the offers' half, `ClaimBonus`, `OpenQuiz`, `AnswerQuiz`, the stream's boxes and quizzes (`PlanetEvent` 3, 4 and 8,
  `reserved`) and their events went to `bonuses.v1`. `planet.v1.BonusKind` and `ChargesHeld` stay planet's (every kind a count since 2026-11-16: `refill`, `bomb` and
  `virus`, booleans, are `reserved` for `refills`, `bombs` and `viruses`, in `GrantChargesRequest` too): they name
  what a hand holds
- `proto/bonuses/v1/bonuses.proto` — what a box caught, a right answer and a sign-in grant (`BonusService`:
  `GetGrantRules`, what the page shows of the bonuses' rules: the sign-in refill, whether the gates are on and the kinds
  open to all, in `planet.v1.BonusKind`). `ClaimBonus`, the stream (`BonusEvent`) and the events
  (`BonusClaimed`, the box facts) went to `boxes.v1` on 2026-11-15, as `OpenQuiz`, `AnswerQuiz` and `quiz_offered` went to
  `quizzes.v1` on 2026-11-13. Beside it, `rules.proto` is `bonuses.v1.Rules`, which postgres also keeps as protojson (the
  quizzes' `quiz`, 10, and the boxes' `boxes`, `offer_ttl`, `miss_retry`, `active_within`, `welcome` and `frozen`
  `reserved`; its `gates` since 2026-11-16); `internal.proto` is `PlayRuleSet`, `GetRuleSetNames` and `GetRuleSet`, for
  the gamemaster and promo; `commands.proto` is `KeepUnlocks`, the kinds an account unlocked, and `PayLevelUp`, a level reached by play, which
  progression sends;
  and `admin.proto` the operator's `GetRules` and `SaveRuleSet` (`bonuses.v1.AdminService`), which Claude calls as
  `bonuses_get_rules` and `bonuses_save_rule_set`
- `proto/boxes/v1/boxes.proto` — the boxes (`BoxService`: `ClaimBox`, which pays nothing, and `ListenForEvents`, a stream
  of `BoxEvent`: `heartbeat` and `box_offered` to the caller alone, with no kind), and `FrozenRefusal`. Beside it,
  `events.proto` is `BoxClaimed`, whose first two fields read as `bonuses.v1.BonusClaimed`'s, with the box's `token` and
  `welcome`, and the box facts (`BoxCaught`, `BoxLapsed`, `ForeignBoxClaimed`) with `bonuses.v1`'s fields and numbers;
  `rules.proto` is `boxes.v1.Rules`; `internal.proto` is `PlayRuleSet`, `GetRuleSetNames` and `GetRuleSet`; and
  `admin.proto` the operator's `GetRules` and `SaveRuleSet` (`boxes_get_rules`, `boxes_save_rule_set`)
- `proto/quizzes/v1/quizzes.proto` — the quizzes (`QuizService`: `OpenQuiz`, `AnswerQuiz`, right or wrong and paying
  nothing, and `ListenForEvents`, a stream of `QuizEvent`: `heartbeat`, `quiz_offered` to the caller alone, `quiz_won` to
  everyone), and `FrozenRefusal`. Beside it, `events.proto` is `QuizAnswered`, whose first three fields read as
  `bonuses.v1.QuizAnswered`'s, with the quiz's `token` and `welcome`; `rules.proto` is `quizzes.v1.Rules`; `internal.proto`
  is `PlayRuleSet`, `GetRuleSetNames` and `GetRuleSet`; and `admin.proto` the operator's `GetRules`, `SaveRuleSet` and
  `ListQuizQuestions`, every question of the bank with its prior, its rating and what its answers measured
  (`quizzes_get_rules`, `quizzes_save_rule_set`, `quizzes_list_quiz_questions`)
- `proto/flags/v1/flags.proto` — the catalog of flags (`FlagService/ListFlags`, public: every flag the game ships with,
  then the ones opened since, the closed ones too, each `Flag{code, name, closed}`, and for one opened since `sold`: its
  `Picture` (public URL, size, `stretch` and focus), `ends_at` and `closed_at`). A flag opened since is `r-` and ten
  letters or digits. Beside it, `events.proto` is `FlagOpened` and `FlagClosed`, which planet keeps in its catalog, and
  `FlagRenamed`, and `admin.proto` the operator's `ListFlags`, `CreateFlagUpload`, `OpenFlag`, `AddTime`, `CloseFlag`
  and `RenameFlag` (`flags_*`), and since 2026-11-24 the review of the players' submissions: `ListSubmissions`
  (`KeptSubmission`), `ApproveSubmission`, `RejectSubmission` (a `Rejection`: its `RejectionReason` and a note) and
  `OpenSubmittedFlag`. A sold flag has a `Pin` (latitude and longitude, never a tile), `Sold.pin`. `FlagService` also
  takes a signed-in player's `CreateSubmissionUpload`, `SubmitFlag` and `ListMySubmissions` (`Submission`, its
  `SubmissionState`). `FlagRenamed` also tells a founder's change approved (a new name or picture). Planet's
  `Allegiance.closed` says the flag held is closed: its account picks another at once. `FlagService/ListenForEvents` is
  its stream: a heartbeat, and each flag opened, closed or renamed while it is open (`flag_changed`), and a page reads
  `ListFlags` as it opens (see the backend's
  [The flags module](../apps/backend/docs/flags.md))
- `proto/chat/v1/chat.proto` — the live chat (`ChatService`). A message, a quote and a reaction carry account ids, never
  a name: the page names them with player's `GetNameplates`
- `proto/auth/v1/auth.proto` — who a caller is (`AuthService`): the mint that gates `Click`, the identity token resumed from the cookie, the caller's account, sign-in with Google, Discord or an emailed code, sign-out and deletion; the `Landing` the calls that make an account carry, with the recruiter's account (`optional`). Beside it, `admin.proto` is the admin page's own sign-in, `WhoAmI` and the connection of an app, and `CountArrivals`, the accounts made each UTC day by `ArrivalSource`, which the Lab page reads and Claude calls as `auth_count_arrivals`
- `proto/player/v1/player.proto` — who a player is: its name and color, who is playing (the roster's stream), a player's public card, `GetPlayer` (name, color, admin, guest, when the account was made, and the last names its player left, `past_names`), and the nameplates the page draws every other name from, `GetNameplates`, and the player that holds a username, `GetPlayerByName`, for a player's address (`PlayerService`). Its `Player` is the one message every read of a player answers, `internal.proto`'s `GetPlayers` and `IntroducePlayer` too; the colors themselves are `NameColor` in `color.proto`. Its stats, titles and fronts went to `progression.v1` on 2026-11-04: their old fields are `reserved`, and so is the roster stream's `title_earned`
- `proto/progression/v1/progression.proto` — how far a player went (`ProgressionService`): the caller's titles, title worn and fronts (`GetTitles`, `WearTitle`, `GetFronts`), the badges of a page of accounts (`GetBadges`: each one's streak and worn title, which the browser keeps and draws beside every name), a player's progress on its public card beside player's `GetPlayer` (`GetProgress`), the caller's level kept on its bar with what each `missions.v1.MissionKind` pays, as `xp` for every `per` of the goal, what each other source of XP pays (`xp_rates`, by `XpSource`), and the ladder: each kind of bonus a level unlocks, in `planet.v1.BonusKind`
(`GetLevel`; the card's `Progress.level` too), and the titles the caller earns, the levels it reaches and the XP each fact gave it, by source, live (`ListenForEvents`: `title_earned`, `level_reached`, `xp_gained`). A title is `Title` in `title.proto`. `chat.proto` and `scoring.proto` carry no badge of their own (their `reserved` lines are the fields that copied one): the page reads them from `GetBadges`. Beside it, `events.proto` is `StatsChanged`, which only progression hears, and `admin.proto` the operator's `ReconcileTitles`, `BackfillDaysPlayed`, `ReconcileLevels` (raise-only, its `lowered`
`reserved`), `ForgiveMissedDay`, one missed day counted on a streak, and `GetProgress`
- `proto/scoring/v1/scoring.proto` — a points accountant's books and rounds, read by the ids the gamemaster's timeline names: a book's board and scores, a round's live standings or results, the caller's tally (`ScoringService`). A standing is an account id, never a name. No season, day or battle: those are the gamemaster's words
- `proto/missions/v1/missions.proto` — the caller's four or five missions of the day, how far it took them, and which are paid, and its flag's mission (`MissionService`: `GetMissions`, and `ListenForEvents`, the same day as the stream opens and again after each fact of the caller, once a second at most); each kind of mission is its own message in a `oneof`, so a new kind adds a message and no field. A mission's reward is `MissionReward.xp {}`, with no amount: the page computes it from progression's `GetLevel.mission_rates` (`charges`, field 1, is `reserved` since missions paid XP). Beside it, `kind.proto` is `MissionKind`, which the operator's totals and `MissionsDone` count by, `events.proto` is `MissionsPaid`, how many missions an account was paid in all, `MissionsDone`, how many it has done in all and, by kind, how many and their goals summed (`KindDone`), a guest's too and paid or not, with no reward in it, and `FlagMissionDone`, a flag's mission done, as its `FlagMission`, which the chat announces, and `admin.proto` the operator's reads of what was given and done (`missions.v1.AdminService`: `ListFlagDays`, every flag's day with its mission, `GetMissionTotals`, the players' missions counted by kind), the numbers missions draws with (`GetRules`, `SaveRules`), whose `Rules` is in `rules.proto`, which postgres also keeps as protojson, and `RetellMissionsDone`, which tells every account's `MissionsDone` once, after the deploy that added it
- `proto/support/v1/support.proto` — what a player sends the operator: a feature suggestion or a bug report, with photos or videos, or a report of another player (`SupportService`). A suggestion and a bug report name the address the operator answers at (`reply_address`, or the account's); a note with none anywhere is refused with a `NoteRefusal` detail. Beside it, `admin.proto` is the operator's notes, each with its conversation by email (`ListNotes`, `AnswerNote`, `CloseNote`), the letters the operator writes to a player first, with the player's replies (`WriteLetter`, `ListLetters`, `CloseLetter`; `Letter`, `LetterMail`), and the reports (`ListReports`, `DecideReport`)
- `proto/gamemaster/v1/gamemaster.proto` — what the schedule plays now, in the players' words: the `Turn`, the kind of the running entry (`EntryKind`: plain or battle), the operator's description of its rules, since when and until when, and the entry's id that scoring's round of its own repeats, never a rule set's name, and the `Timeline`, the battles to come (`GamemasterService`: `ListenForEvents`, the turn and the timeline then each change of either, and `GetTurn`, the same as a cached GET, `GetSeasonTotals`, an ended season's `planet.v1.LedgerTotals`, and `GetSeasonReplay`, its `planet.v1.MapHistory`); the timeline carries the season that runs, the next
one, the ones that ended (each with its finale's round), today's day, and each battle's times, all with the ids of their books and rounds in scoring, and the stream tells each `Debrief`: a day, a battle or a season scoring scored. Beside it, `events.proto` is what the gamemaster tells the other modules in the game's words (`SeasonStarted`, `DayStarted`, `BattleStarted`, `DayEnded`, `BattleEnded`, `SeasonEnded`). Beside it, `admin.proto` is the rule schedule: which rule set planet, the antibot and the offers play (and the battles scoring scores), of which kind, with which words for the players, and when (`gamemaster.v1.AdminService`: `GetSchedule`, `AddEntry`, `EditEntry`, `DeleteEntry`), and the seasons, each with its optional finale, the Final Battle (`GetSeasons`, `AddSeason`, `EditSeason`, `DeleteSeason`; `GetSchedule` lists the finales beside the entries)
- `proto/alerts/v1/alerts.proto` — the game's Discord server (`AlertsService`): whether it is offered, whether the caller is in it, and its page. A player joins it by signing in with Discord: `auth` tells it (`auth.v1.DiscordJoinGranted`) and keeps the token for `auth.v1.InternalService/GetDiscordGrant`, so alerts has no internal service. Beside it, `admin.proto` is the operator's read and unlink of an account's link, and the run that links the players already in the server and gives every linked one its username as its nickname (`alerts.v1.AdminService`: `GetPlayerLink`, `UnlinkPlayer`, `LinkMembers`)
- `proto/antibot/v1/admin.proto` — the operator's bans, warnings and rules (`antibot.v1.AdminService`: `BanPlayer`, `UnbanPlayer`, `WarnPlayer`, the jury's "One account per player" warning given to an account by hand, `InspectPlayer`, `GetRules`, `SaveRuleSet`). Beside it, `antibot.proto` is its one public service (`antibot.v1.AntibotService`): the caller's warning for playing several accounts, and its notice that another account played from its connection at the same time (which bans nothing), each as the stream opens while it is not acknowledged and as it is given (`ListenForEvents`), and their acknowledgements (`AcknowledgeWarning`, `AcknowledgeNotice`). `InspectPlayer` answers the notice too (`noticed_at`, `noticed_alongside`, `notice_acknowledged_at`). And `rules.proto` is `antibot.v1.Rules`, every bound of a rule set, which postgres also keeps as protojson
- `proto/promo/v1/promo.proto` — what the game shows of a battle before it starts (`PromoService`: `GetTeaser`, a battle's cards by the id the gamemaster's timeline names it by, each a public background URL and words already filled with the values its rule set plays and the battle's points, as a cached GET). Never a rule set's name. Beside it, `admin.proto` is the operator's library of backgrounds and each set's cards (`promo.v1.AdminService`: `CreateBackgroundUpload`, `KeepBackground`, `ListBackgrounds`, `RemoveBackground`, `GetCards`, `SaveCards`), for the backoffice's Promo page, the battles to come with their cards (`ListTeasers`), and each battle's teaser posted on TikTok and YouTube (`ListDueTeasers`, `PostTeaser`), which the teasers job calls once it rendered the cards; `GetCards` fills the cards as in an `ExampleBattle`, a ×3 one, since a set has no battle of its own
- `proto/publishing/v1/admin.proto` — the game's posts on its own TikTok and YouTube (`publishing.v1.AdminService`:
  `CreateMediaUpload`, a link to upload a video, or a JPEG of a TikTok carousel, to the posting service's storage; `GetRoom`, how many posts each
  platform takes now; `PlanPost`, the slot a post would take, or with `by` the one where every platform asked takes it; `SchedulePost`, a post at that slot, answered as
  scheduled, busy, taken or failed, with photos in place of the video on TikTok when it has them; `ListPosts`, every post on the service with the metadata it was posted with; `ListSnapshots` and `ListRows`, the daily snapshots of the posts' numbers the server takes, for the backoffice). No
  public service: the clips job calls it over SSH. Beside it, `internal.proto` is `PlanPost`, `SchedulePost` and `ListPosts` again, in the same messages, for promo, which posts each battle's teaser, and `GetPostLinks`, each post's address, for clips (`publishing.v1.InternalService`). A platform is the `Platform` enum
- `proto/vandalsquad/v1/admin.proto` — the swastikas players painted on the map that the vandal squad flagged (`vandalsquad.v1.AdminService`: `ListGraffiti`, each with its painter, its flag, its tiles and a link to it). No public service and no internal one: the squad reads planet's ledger (`planet.v1.InternalService/GetLedger`), asks planet `planet.v1.InternalService/GetTiles` (each tile's flag, holder, point and neighbours), hears `player.v1.PlayerForgotten`, and answers only the operator
- `proto/clips/v1/clips.proto` — what the frontend's clip generator hands the backend's job that posts its clips: the findings its model editor makes the stories from (every front, tour and place measured, with their top fighters, each place's saga over the season and each ruling flag's land on each continent over it, the season's stories, and a carousel's three `Lists`), the story the job hands back to render (`Pick`, a carousel's `list` and `ranks` too), what to post with each clip (a carousel's `photos`, and its record's `Carousel`), and a run's `Cast` (numbers and names, never an account). No service: all are written as JSON files in one workflow run. Beside it, `admin.proto` is the players each clip names (`clips.v1.AdminService`: `MakeCast`, `KeepAppearance`), which the job keeps over ssh. The same service keeps the videos the operator posts by hand (`CreateVideoUpload`, `KeepVideo`, `ListVideos`, `RemoveVideo`), for the backoffice's Videos page. And which names the posts may show, as the judge or the operator decided (`ListNameVerdicts`, `SetNameVerdict`). `appearances.proto` is the public `ClipsService`: the posts that name the caller, whether the clips may name it, and, with no token, of a page of accounts the names a player's video may show (`GetShownNames`)

Beside them, `internal.proto` is what one backend module asks another, or `auth`'s admin gate asks `auth` (`auth.v1`, `player.v1`, `planet.v1`, `boxes.v1`, `bonuses.v1`, `quizzes.v1`, `antibot.v1`, `scoring.v1`, `gamemaster.v1`, `publishing.v1`; `player.v1.InternalService/GetAccounts` is what auth says of an account, for a module that must not ask auth), `events.proto` is what one tells the others over Redis Streams (among them `planet.v1.TilesTaken`, one per act on the map however many tiles it took, `planet.v1.AllegiancePledged`, `planet.v1.FlagKnockedOut`, `planet.v1.ClickTried`, `boxes.v1.BoxClaimed`, `quizzes.v1.QuizAnswered`, `chat.v1.MessageSent`, `chat.v1.AccountMuted`, `auth.v1.AccountDeleted`, `auth.v1.DiscordJoinGranted`, `player.v1.PlayerCreated`, `player.v1.PlayerNamed`, `player.v1.PlayerSignedIn`, `player.v1.PlayerLeaving`, `player.v1.PlayerReturned`, `player.v1.PlayerForgotten`, `gamemaster.v1.SeasonEnded`, `progression.v1.StatsChanged`, `missions.v1.FlagMissionDone`, `support.v1.PlayerReported`), and `commands.proto` is what one asks another to change, in the receiver's words (`planet.v1.GrantCharges`, which missions sent until missions paid XP, `planet.v1.RefuseCaller` and `planet.v1.AdmitCaller`, which the antibot sends, `scoring.v1.GrantPoints`, which missions sends, `support.v1.DecideReport`, which the chat's judge sends, and `bonuses.v1.KeepUnlocks` and `PayLevelUp`, which progression sends). What the gamemaster asks scoring, planet, the antibot and the offers to change are calls on their `internal.proto`, answered at once: `scoring.v1.InternalService/OpenBook`, `OpenRound`, `CloseRound` and `CloseBook`, `planet.v1.InternalService/OpenArena`, `CloseArena`, `ResetMap` and `PlayRuleSet`, `antibot.v1.InternalService/PlayRuleSet`, `boxes.v1.InternalService/PlayRuleSet`, `bonuses.v1.InternalService/PlayRuleSet` and `quizzes.v1.InternalService/PlayRuleSet`. So is what the bonuses module and the boxes ask planet: `planet.v1.InternalService/GrantCharges`, a grant answered at once, once per `grant_id`, `FillCharges`, every stack named filled to its size, once per `grant_id`, for a level reached, and the read `GetFreeze` (`GetChargesOf` went on 2026-11-13, `GetRoom` on 2026-11-16). `planet.v1.InternalService/GetTiles` is each tile asked as the map holds it now, for the vandal squad. `gamemaster.v1.InternalService/GetBattle` is what a battle plays (its set and its points' times), `GetTimeline` the battles to come, for promo's `ListTeasers`, and `scoring.v1.InternalService/GetRankPoints` what each rank of a round of some times scores, both for promo's teaser. None is on the public router; the frontend generates them without using them. `planet.v1`'s `ledger.proto` is the ledger's read, served on its `AdminService` and its `InternalService` alike. `admin.proto` is what an operator calls (`AdminService`, in `alerts.v1`, `antibot.v1`, `auth.v1`, `bonuses.v1`, `boxes.v1`, `chat.v1`, `clips.v1`, `missions.v1`, `planet.v1`, `player.v1`, `progression.v1`, `gamemaster.v1`, `promo.v1`, `publishing.v1`, `quizzes.v1`, `support.v1` and `vandalsquad.v1`): over SSH on the console listener, and from the admin page on the admin listener, which only a signed-in operator passes. Claude calls them there too, as a connector the operator lets in once ([Claude as a connector](../apps/backend/docs/connector.md)).

**Every admin rpc keeps a comment, against the repo's no-comments default**: it is the description of the connector's tool, the text Claude reads before it calls, and the backend's tests fail on a method with none. A field's comment is that field's description in the tool's input. A read marked `NO_SIDE_EFFECTS` is a read-only tool.

Connect derives each service's route from its proto package, so a new context gets its own path with no prefix to allocate. Every `buf.gen.yaml` input points at the whole `proto` directory, so a new package is picked up by each generator with no config change.

After editing a `.proto`:

```bash
cd apps/backend && make proto   # regenerates apps/backend/generated/proto
cd apps/frontend && npm run proto   # regenerates apps/frontend/src/gen/grpc
cd apps/backoffice && npm run proto   # regenerates apps/backoffice/src/gen/grpc
```

Every app's `buf.gen.yaml` reference `../../proto` (or `../../../proto` for the backend, whose config lives one level deeper at `apps/backend/proto/`) — do not create per-app copies of the `.proto` files again.

**A change of the game's wire is a hard switch**: a page reloads when the backend restarts, so no tab keeps calling
an old path or reading an old field (see [A server restart reloads the page](reload-on-restart.md)). A removed field's
number and name are still `reserved`, never reused. The backoffice does not reload: an operator's call changed at once
needs the admin page reloaded by hand.
