# Translation

**The game page speaks the player's language**: English, French (`fr`), German (`de`), Turkish (`tr`), Brazilian
Portuguese (`pt-BR`), Polish (`pl`), Indonesian (`id`), Spanish (`es`, neutral) and Czech (`cs`). In Nov 2026 those
were 90% of the networks that click. Everything is in `src/i18n/`, hand-rolled and small: no i18n library.

What stays English for now: everything the backend writes (title names and feats, the quiz, battle and finale
descriptions, teaser cards, the clip title, the sign-in email, Discord pings, guest names), the home page
(`index.html`), `privacy.html`, `terms.html`, the OG image, and `src/clip`, `src/teaser`, `src/video` with
`domain/teaserFrame.ts`. Players' chat and names are never translated, nor are the backoffice and the anthem titles.

## The catalogue

- **`locales/en.json` is the source**: one key per whole sentence, `area.what` in camelCase (`chat.reportSent`).
  The other languages are one file each, `locales/<tag>.json`, with the same keys. `Key` is typed from `en.json`, so a
  wrong key fails `tsc`.
- **Only the player's language is downloaded** (`load.ts`, a dynamic import per file); English is in the bundle and
  fills any line a file lacks.
- **`notes.json`** gives the translator a note for a line whose code does not say what it means ("Big", "Off"). The
  page never loads it.
- **`fingerprints/<tag>.json`** holds the fingerprint of the English each line was translated from: the backend's
  [translator](../../backend/docs/translate.md) sends only new or changed lines, and keeps a hand fix.
- **`landmasses/<tag>.json`**: the landmass names of `static/landmassNames.json` in each language, keyed by id, read
  with the lines. A country's main landmass is the country's name.
- **`countries/<tag>.json`**: each flag's country inside a sentence, in every language and English too, keyed
  `in.<code>` for each flag of `static/countries/countries.json`, read with the lines (below).
- **`catalogue.test.ts` fails** when a language's file lacks a key, holds one `en.json` no longer has, has a line that
  does not parse, names other slots than English, or misses a plural category its language needs (each language's
  `Intl.PluralRules` categories: Polish and Czech have `one`, `few`, `many`, `other`; French, Spanish and Portuguese
  `many` for a million), when a landmass file lacks a name, and when a country file lacks a flag or a phrase has
  another slot than `{flag}`.

## A line

A line is a subset of ICU MessageFormat (`message.ts`):

- `{player}`: a slot. Named for what it holds. A number in it is formatted in the page's locale.
- `{count, plural, one {# tile} other {# tiles}}`, with `=0 {…}` for an exact count; `#` is the number. When English
  says "a" for one, the branch says it: `{goal, plural, one {Catch a box} other {Catch # boxes}}`.
- `{rank, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` (`format.ordinal`, used by `ordinal()`).
- `{kind, select, a {…} other {…}}`.
- `<terms>…</terms>` around words the page wraps in an element (a link, bold).
- No escapes: a brace is always syntax, an apostrophe always a letter.

**One whole sentence per key.** A sentence is never glued from two lines or cut around an element: the element goes
in a slot (`rich("chat.knockedOut", {winner: <strong>…</strong>, loser: …})`), so each language puts it where its
grammar wants.

## In the code

```ts
import {t, translator} from "../i18n/page.ts"
import {rich} from "../i18n/rich.tsx"

t("missions.title")
t("mission.order.catchBoxes", {goal: 3})
rich("signIn.agree", {terms: (children) => <a href="/terms">{children}</a>})
translator().country("fr")        // Intl.DisplayNames, and our lines for xb, xk, gb-eng/sct/wls, cd, cg, sx, va
translator().countryIn("br", flag) // "au {flag} Brésil": "in" the country, as the language says it
translator().landmass(id, ground)
translator().number(n, options)   // and dateTime, dateTimeRange, ago, countdown, length, ordinal, list, compare
```

- **Never at a module's top level**: the language loads after the modules run. A table of labels is a table of keys.
- **`domain/` returns facts**, never words or a locale: a kind, a number, a `Countdown`. The words are chosen in
  `app/`, where a function may call `t()`.
- **Every number, date, time, list, ordinal and duration comes from Intl in the page's locale** (`translator()`):
  never `"en-GB"`, `toLocaleString()` or `new Intl.*(undefined, …)`. The locale is the browser's own tag when it
  speaks the language chosen ("en-GB" for English), so dates and digits look as the player expects.
- **Country names come from `Intl.DisplayNames`**, short when that is not an abbreviation ("Bosnia", not "UK"),
  without a parenthesis ("Myanmar"). The flags ISO has no code for, the codes CLDR names as two places ("Congo -
  Kinshasa"), and the ones it names by the state's long title ("État de la Cité du Vatican") have a `country.<code>`
  line (`OWN_COUNTRY_NAMES`). `static/countries/countries.json` is the list of flags; its English names are only the
  clips'.

## A country inside a sentence

**"In" a country is a phrase of its own in each language**, never a preposition in the line before a name: French
says "en Argentine", "au Brésil", "aux États-Unis", "à Cuba"; Portuguese "na Argentina", "no Brasil"; German "in der
Schweiz", "im Iran"; Polish and Czech change the name's ending ("w Argentynie", "v Argentině"); Turkish adds a suffix
("Arjantin'de"); English "in the United States". So `countries/<tag>.json` holds, for each flag, the phrase with
`{flag}` where its picture goes: `"in.br": "au {flag} Brésil"`. A line takes it whole in a slot, `{where}`, and
writes no preposition around it: `"Prends # cases {where}"`.

- `translator().countryIn(code, <CountryFlag code={code}/>)` gives the parts with the flag in place,
  `countryInText(code)` the words alone (`app/missions/orderParts.tsx` uses both).
- A phrase a language lacks is English's; one English lacks is the flag and the name.
- The backend's [translator](../../backend/docs/translate.md) writes them from `countries.json`, so a new flag gets
  its phrase in every language at the next `make translate`.
- **Tests run in English**: the page's translator is English until `speak()`. A test of another language builds
  its own `Translator`.

## Choosing the language

`speakChosenLanguage` (`start.ts`) runs before the page draws, in `main.tsx` and `archive.tsx`:

1. **The player's pick** in the settings (`LanguagePicker`, kept in local storage under `clickplanet-language`). A
   pick reloads the page: every line is read once.
2. **On CrazyGames, the portal's language**: the SDK's `user.systemInfo.locale`, waited for 2 s at most.
3. **The browser's**: the first of `navigator.languages` the game has. Every `pt-*` is `pt-BR`, every `es-*` is
   `es`, and `sk` is `cs`, since Slovak players read Czech.
4. English.

The page sets `<html lang>`, and every Connect call sends the language as `Accept-Language`
(`backends/language.ts`). It is a CORS-safelisted header, so it adds no preflight; the fakes have no transport. The
backend ignores it for now.

## Adding a string

1. Write the English in `locales/en.json` (a new area gets a new prefix), and a note in `notes.json` if its code
   does not say what it means.
2. Use it with `t()` or `rich()`.
3. `ANTHROPIC_API_KEY=... make translate` in `apps/backend` writes it into every language and its fingerprint. A
   line can also be written by hand into each file: the next run fingerprints it.
4. `npm test`.

Changing an English line sends it again at the next run, in every language.

## Adding a language

1. An empty `{}` in `locales/<tag>.json` and `landmasses/<tag>.json`.
2. Its tag in `LANGUAGES` (`languages.ts`), and in `BY_PRIMARY` the primary tags that read it.
3. Its word for each term of the backend's `internal/translation/glossary.json`, and its informal "you" in
   `claude_translator/instructions.md`.
4. `make translate`, then read it, and check the screens at phone size: German runs about 30% longer than English.

## The display face

**Luckiest Guy draws Latin Extended too**: Google Fonts serves it a `latin-ext` subset, loaded by `unicode-range`
when a page shows such a letter, so Polish, Czech and Turkish (`Ł`, `ř`, `ş`, `İ`) are drawn in it, not in a
fallback (checked Nov 2026: a glyph's width in it is the same over a serif and a monospace fallback). A canvas
draws with a font only once it is loaded: what draws on one (`drawShareCard.ts`) loads the face for its own text
first. Cyrillic, Greek and every other script are not in it: a language in one needs another display face.
