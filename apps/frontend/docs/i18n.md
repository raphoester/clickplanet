# Translation

**The game page speaks the player's language**: English, French (`fr`), German (`de`), Turkish (`tr`), Brazilian
Portuguese (`pt-BR`), Polish (`pl`), Indonesian (`id`), Spanish (`es`, neutral) and Czech (`cs`). In Nov 2026 those
were 90% of the networks that click. Everything is in `src/i18n/`, hand-rolled and small: no i18n library.

What stays English for now: everything the backend writes (title names and feats, the quiz, battle and finale
descriptions, teaser cards, the clip title, the sign-in email, Discord pings, guest names), the home page
(`index.html`), `privacy.html`, `terms.html`, the OG image, and `src/clip`, `src/teaser`, `src/video` with
`domain/teaserFrame.ts`. Players' chat and names are never translated, nor are the backoffice and the anthem titles.

## The catalogue

- **`locales/en.json` is the source**: one key per whole sentence, `area.what` in camelCase (`chat.reportSent`).
  The other languages are one file each, `locales/<tag>.json`, with the same keys. `Key` is typed from `en.json`, so a
  wrong key fails `tsc`.
- **Only the player's language is downloaded** (`load.ts`, a dynamic import per file); English is in the bundle and
  fills any line a file lacks.
- **`notes.json`** gives the translator a note for a line whose code does not say what it means ("Big", "Off"), and
  **`glossary.json`** the game's words and the one chosen in each language. The page never loads them.
- **`fingerprints/<tag>.json`** holds the fingerprint of the English each line was translated from: only new or
  changed lines are translated again, and a hand fix stays ([Translating](#translating)).
- **`landmasses/<board>/<tag>.json`**: each board's landmass names in each language, keyed by the landmass id of that
  board, since an id is a row of one board's borders file. English is the board's own file,
  `static/boards/<board>/landmassNames-<hash>.json` (see [Static assets](static-assets.md)). The game page reads both
  once it knows its board (`landmassNamesOf` in `load.ts`) and hands them to `translator().nameLandmasses`; until then,
  and on another page, a landmass reads as its country. A country's main landmass is the country's name. A board with
  no file in a language reads English: none waits since PR 5 wrote `siege-1`'s (`AWAITING_TRANSLATION` in
  `catalogue.test.ts`, see [Landmass names](#landmass-names)).
- **`countries/<tag>.json`**: each flag's country inside a sentence, in every language and English too, keyed
  `in.<code>` for each flag of `static/countries/countries.json`, read with the lines (below).
- **`catalogue.test.ts` fails** when a language's file lacks a key, holds one `en.json` no longer has, has a line that
  does not parse, names other slots than English, or misses a plural category its language needs (each language's
  `Intl.PluralRules` categories: Polish and Czech have `one`, `few`, `many`, `other`; French, Spanish and Portuguese
  `many` for a million), when a board's landmass file lacks a name or names a board the page does not carry, and when a
  country file lacks a flag or a phrase has another slot than `{flag}`.

## A line

A line is a subset of ICU MessageFormat (`message.ts`):

- `{player}`: a slot. Named for what it holds. A number in it is formatted in the page's locale.
- `{count, plural, one {# tile} other {# tiles}}`, with `=0 {…}` for an exact count; `#` is the number. When English
  says "a" for one, the branch says it: `{goal, plural, one {Catch a box} other {Catch # boxes}}`.
- `{rank, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` (`format.ordinal`, used by `ordinal()`).
- `{kind, select, a {…} other {…}}`.
- `<terms>…</terms>` around words the page wraps in an element (a link, bold).
- No escapes: a brace is always syntax, an apostrophe always a letter.

**One whole sentence per key.** A sentence is never glued from two lines or cut around an element: the element goes
in a slot (`rich("chat.knockedOut", {winner: <strong>…</strong>, loser: …})`), so each language puts it where its
grammar wants.

## In the code

```ts
import {t, translator} from "../i18n/page.ts"
import {rich} from "../i18n/rich.tsx"

t("missions.title")
t("mission.order.catchBoxes", {goal: 3})
rich("signIn.agree", {terms: (children) => <a href="/terms">{children}</a>})
translator().country("fr")        // Intl.DisplayNames, and our lines for xb, xk, gb-eng/sct/wls, cd, cg, sx, va
translator().countryIn("br", flag) // "au {flag} Brésil": "in" the country, as the language says it
translator().landmass(id, ground)
translator().number(n, options)   // and dateTime, dateTimeRange, ago, countdown, length, ordinal, list, compare
```

- **Never at a module's top level**: the language loads after the modules run. A table of labels is a table of keys.
- **`domain/` returns facts**, never words or a locale: a kind, a number, a `Countdown`. The words are chosen in
  `app/`, where a function may call `t()`.
- **Every number, date, time, list, ordinal and duration comes from Intl in the page's locale** (`translator()`):
  never `"en-GB"`, `toLocaleString()` or `new Intl.*(undefined, …)`. The locale is the browser's own tag when it
  speaks the language chosen ("en-GB" for English), so dates and digits look as the player expects.
- **Country names come from `Intl.DisplayNames`**, short when that is not an abbreviation ("Bosnia", not "UK"),
  without a parenthesis ("Myanmar"). The flags ISO has no code for, the codes CLDR names as two places ("Congo -
  Kinshasa"), and the ones it names by the state's long title ("État de la Cité du Vatican") have a `country.<code>`
  line (`OWN_COUNTRY_NAMES`). `static/countries/countries.json` is the list of flags; its English names are only the
  clips'.

## A country inside a sentence

**"In" a country is a phrase of its own in each language**, never a preposition in the line before a name: French
says "en Argentine", "au Brésil", "aux États-Unis", "à Cuba"; Portuguese "na Argentina", "no Brasil"; German "in der
Schweiz", "im Iran"; Polish and Czech change the name's ending ("w Argentynie", "v Argentině"); Turkish adds a suffix
("Arjantin'de"); English "in the United States". So `countries/<tag>.json` holds, for each flag, the phrase with
`{flag}` where its picture goes: `"in.br": "au {flag} Brésil"`. A line takes it whole in a slot, `{where}`, and
writes no preposition around it: `"Prends # cases {where}"`.

- `translator().countryIn(code, <CountryFlag code={code}/>)` gives the parts with the flag in place,
  `countryInText(code)` the words alone (`app/missions/orderParts.tsx` uses both).
- A phrase a language lacks is English's; one English lacks is the flag and the name.
- [Translating](#translating) writes them from `countries.json`, so a new flag gets its phrase in every language at
  the next run.
- **Tests run in English**: the page's translator is English until `speak()`. A test of another language builds
  its own `Translator`.

## Translating

**Translation is a Claude Code job** (the owner, 2026-11-18: no API credits for it): the
[`translate` skill](../../../.claude/skills/translate/SKILL.md) gives each batch of lines to a Haiku subagent, and no
code calls an API. The backend's `cmd/translations` does the bookkeeping, with no network and no key:

```bash
cd apps/backend
go run ./cmd/translations plan -work <folder>   # what each language lacks, as batch files
go run ./cmd/translations apply -work <folder>  # the answers beside them, checked and written with their fingerprints
```

- **Four kinds of catalogue**: the page's lines (`locales/en.json` → `locales/<tag>.json`), each board's landmass
  names (`static/boards/<board>/landmassNames-<hash>.json` → `landmasses/<board>/<tag>.json`), each board's province
  names (`provinceNames-<hash>.json` → `provinces/<board>/<tag>.json`, `earth-2` and `siege-1`), and "in" each flag's
  country (`static/countries/countries.json` → `countries/<tag>.json`, English too). The languages are the files of
  `locales/`.
- **Only a line that is new, or whose English changed, is planned.** Its fingerprint is the first 16 hex digits of the
  SHA-256 of the English it was translated from, in `fingerprints/<tag>.json` (`fingerprints/landmasses/<board>/`,
  `fingerprints/countries/`). A line whose English is the same is never planned again, so a hand fix stays. A line with
  no fingerprint was written by hand: the next `apply` keeps it and fingerprints it. A key English no longer has is
  dropped.
- **A batch** is `<folder>/<catalogue>/<tag>.<n>.json`, at most 400 lines (`-batch`), each with its key, its English
  and its context: a page line's note and the first lines of code that show it (`file: line`, the quoted key searched
  in `src/`), a landmass's trailing number and Natural Earth's names, a country's ISO code. The subagent writes its
  answers beside it, `<tag>.<n>.answers.json`, a JSON object of keys and translations. `plan` refuses a folder that is
  not empty, so no older answer is taken.
- **The subagent reads** the skill's [`instructions.md`](../../../.claude/skills/translate/instructions.md): the tone
  (short sentences, a teenager's game words, the informal "you" of each language, neutral Spanish, Brazil's
  Portuguese), how a line is written (its slots, plural categories, tags), place names, and a country in a sentence.
  For the page's lines it also gets `glossary.json` and its language's plural categories, from `Intl.PluralRules`.
- **`apply` refuses an answer** that is empty, does not parse, or loses a slot or a tag (`translation.SlotsDiffer`, the
  same subset of ICU as `message.ts`), and fails naming every line still not translated: the next `plan` gives them
  again. A count may become a plain `{count}` in a language with one form for every number; `catalogue.test.ts` then
  checks every plural category each language needs.
- The files keep `en.json`'s order, two spaces deep, `<` and `&` as they are.

### Landmass names

**A landmass id is a row of one board's borders**, so each board's names are a catalogue of their own. But a name one
board translates is the same on another: `plan` gives a landmass the name another board gives the same English in that
language, or the same English before a trailing number ("Ionian Islands 2" is "Îles Ioniennes 2"), the first board by
name first. So 615 of `earth-2`'s 936 names are `earth-1`'s, and Haiku wrote the other 321 in each language
(2026-11-18). A board with no names file yet is left out.

**Natural Earth (`v5.1.2`) names most places** in French, German, Spanish, Portuguese, Polish, Turkish and Indonesian
(not Czech), but as a gazetteer does: "Gespanschaft Split-Dalmatien", "Kabupaten Split-Dalmatia". So its names are a
reference, not a copy: each landmass line carries the ones every place of that English name agrees on, read from the
cache `npm run landmassNames` downloads (`node_modules/.cache/natural-earth/<tag>`). `plan` says when the cache lacks a
layer, and the lines go without.

**`siege-1`'s came with PR 5** of [Boards](../../../docs/boards.md), written the same way before this tool (2026-11-18):
101 of its 135 names are `earth-1`'s same English, and Haiku wrote the other 34, with their fingerprints. No board waits
now: `AWAITING_TRANSLATION` in `catalogue.test.ts` is empty, and the test fails on a board translated and still listed.

### Province names

**A province id is a row of one board's provinces file**, and each board's province names are a catalogue of their own
(see [Provinces](../../../docs/provinces.md#names)). `plan` gives a province the name a board's landmass or province of
the same English has in that language, then Natural Earth's own (`place_source.NaturalEarth`): where every place of that
English agrees on it, and it has no more words than the English, since Natural Earth names a unit with its kind of
division ("İsfahan Eyaleti", "Gespanschaft Split-Dalmatien"). Haiku writes the rest, and all of Czech. 2026-11-18:
`earth-2`'s 1,976 names first, then `siege-1`'s 622, so `siege-1` took `earth-2`'s same English (99 to 102 lines a
language left for Haiku). `catalogue.test.ts` checks every province of every board in every language. The page does not
read them yet (PR 4 of [Provinces](../../../docs/provinces.md)).

### Code

- `apps/backend/cmd/translations`: `flags`, then `page_catalogues.Load` (the plans), and `WriteBatches` with
  `display.Plan`, or `page_catalogues.Apply` with `display.Outcomes`.
- `apps/backend/internal/translation`: `PlanOf` (with a `Memory`: the other boards' names, for a landmass), `Apply`,
  `FingerprintOf`, `SlotsDiffer`. `page_source`, `place_source` (landmass and province names) and `country_source` read each kind's English and
  context, `catalogue_files` reads and writes a catalogue, `natural_earth` reads the cache.

## Choosing the language

`speakChosenLanguage` (`start.ts`) runs before the page draws, in `main.tsx` and `archive.tsx`:

1. **The player's pick** in the settings (`LanguagePicker`, kept in local storage under `clickplanet-language`). A
   pick reloads the page: every line is read once.
2. **On CrazyGames, the portal's language**: the SDK's `user.systemInfo.locale`, waited for 2 s at most.
3. **The browser's**: the first of `navigator.languages` the game has. Every `pt-*` is `pt-BR`, every `es-*` is
   `es`, and `sk` is `cs`, since Slovak players read Czech.
4. English.

The page sets `<html lang>`, and every Connect call sends the language as `Accept-Language`
(`backends/language.ts`). It is a CORS-safelisted header, so it adds no preflight; the fakes have no transport. The
backend ignores it for now.

## Adding a string

1. Write the English in `locales/en.json` (a new area gets a new prefix), and a note in `notes.json` if its code
   does not say what it means.
2. Use it with `t()` or `rich()`.
3. Run the [`translate` skill](#translating): Haiku subagents write it into every language, and `cmd/translations
   apply` its fingerprint. A line can also be written by hand into each file: the next `apply` fingerprints it.
4. `npm test`.

Changing an English line plans it again at the next run, in every language.

## Adding a language

1. An empty `{}` in `locales/<tag>.json` and in `landmasses/<board>/<tag>.json` for each board.
2. Its tag in `LANGUAGES` (`languages.ts`), and in `BY_PRIMARY` the primary tags that read it.
3. Its word for each term of `glossary.json`, and its informal "you" in the skill's
   [`instructions.md`](../../../.claude/skills/translate/instructions.md).
4. The [`translate` skill](#translating), then read it, and check the screens at phone size: German runs about 30%
   longer than English.

## The display face

**Luckiest Guy draws Latin Extended too**: Google Fonts serves it a `latin-ext` subset, loaded by `unicode-range`
when a page shows such a letter, so Polish, Czech and Turkish (`Ł`, `ř`, `ş`, `İ`) are drawn in it, not in a
fallback (checked Nov 2026: a glyph's width in it is the same over a serif and a monospace fallback). A canvas
draws with a font only once it is loaded: what draws on one (`drawShareCard.ts`) loads the face for its own text
first. Cyrillic, Greek and every other script are not in it: a language in one needs another display face.
