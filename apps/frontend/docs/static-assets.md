# Static assets

These assets are **content-addressed**, because `public/_headers` caches
`/static/*` for a week, and each hash-named file below for a year, as
`immutable`: a regenerated file under a stable name would be served stale. A new
kind of hash-named file needs its own `_headers` rule. Each has a generated TS module holding its current URL — do not
edit those by hand, and do not add a `?ts=` cache-buster, which defeats the
cache entirely:

- `/static/boards/<board>/` — each board's files, for every board in `/map` (`earth-1`, the world's; `earth-2` and
  `siege-1`, which nothing plays yet), every one content-addressed: its manifest
  (`board-<hash>.json`), its runs (`runs-<hash>.bin`, which lattice points are tiles: `points.ts`
  rebuilds every tile's position from them in a worker, see [Tile positions](tile-positions.md)),
  its borders (whose ground each tile sits on, fetched by `borderField.ts`), and its capitals and
  bridges (fetched by `capitals.ts` and `bridges.ts` the first time a capitals' rule or the reach
  plays, see [The capitals](capitals.md) and [The reach](reach.md)), and its terrain (each lattice point's kind of
  land or sea, fetched by `terrain.ts` with the globe, see [The terrain](terrain.md)). Beside them, **the page's own
  files of the board**, which `/map` does not carry: its border lines and its landmass names (below). `boardsAsset.ts`
  holds every board's manifest, its own files and each file's URL as `BOARDS`, keyed by the board's name, and
  `viewer/boards.ts` finds one (`boardOf`, which throws on a board this build does not carry). A board missing one of its
  own files is left out of the table, and `npm run map` says which command writes it. Formats in
  [`/map/README.md`](../../../map/README.md#format).
  **These are not ours alone.** The source of truth is the monorepo-shared
  [`/map`](../../../map/README.md), which the backend builds its tile adjacency from
  and its admin tools read; `static/boards/` holds a generated copy, exactly as
  `src/gen/grpc/` holds a copy of the proto contract. `npm run map` re-copies every
  board, sweeps the copies of files `/map` no longer has (never the page's own files) and rewrites `boardsAsset.ts`;
  `npm run map:generate` rewrites the runs, the borders and the
  capitals — one command, because a tile exists exactly where the borders say a country does and the
  two must not be able to disagree — and `npm run bridges` and `npm run terrain` the bridges and the terrain after
  it. **Run the backend's
  `make map` and the backoffice's `npm run map` after them, and commit every copy**, or the apps
  disagree about what a tile id means. A regeneration renumbers every tile, so it also writes the
  postgres migration that follows the owned ones across; see `/map/README.md`. One `_headers` rule
  keeps the whole directory a year, immutable.
- `/static/boards/<board>/borderLines-<hash>.bin` — a board's countries' outlines, traced onto its
  lattice, with the two landmasses each run is between, fetched at runtime by
  `borderLines.ts`. URL in `BOARDS`. Regenerate with `npm run borderLines -- <board>` (every board with none named),
  which reads the board's runs and borders — and **regenerate it whenever either of them changes**,
  or the outline is drawn around a map nobody is playing on. Unlike them it is this
  app's alone and is not in `/map`.
- `/static/boards/<board>/landmassNames-<hash>.json` — the English names of a board's landmasses that are not a
  country's main one, keyed by its borders file (which the file names) and its landmass ids, fetched by `landmassNamesOf`
  once the page knows its board (see [Translation](i18n.md)). Regenerate with `npm run landmassNames -- <board>` after
  the board's borders change. The backend's `make translate` reads it, and writes each language's names in
  `src/i18n/landmasses/<board>/`.
- `/static/countries/atlas-<hash>.png` — the flag sprite atlas. URL and pixel
  size in `atlasAsset.ts`. Regenerate with `npm run atlas`.
- `/static/reactions/<name>-<hash>.svg` — the chat's reaction images. URLs in
  `app/chat/reactionsAsset.ts`. Regenerate with `npm run reactions` — see
  [Reactions](chat.md#reactions).

`/static/og-source.png`, the raw screenshot the social preview is built from, is kept in the repo but **not
deployed** (`copy:static` deletes it from `dist/static/`). **`copy:static` fails the build on a board directory missing
any of its files**: the manifest, the runs, the borders, the capitals, the bridges, the terrain, the border lines and the
landmass names, naming the command that writes it. No photo of the earth is served: the terrain's source,
`scripts/map/earth.jpg`, is read by `npm run terrain` alone.

`/static/og-image-<hash>.jpg` is that preview, generated by `npm run og-image` at
the 1200×627 scrapers ask for; the script also rewrites its URL in `index.html`,
`play.html` and `archive.html`. It is content-addressed because **scrapers cache a preview by
its URL**: under a fixed name, a link shared after a new screenshot still showed
the old one. If you regenerate it at a different size, update
`og:image:width` / `og:image:height` in the three pages to match.

The source is the home page's hero, taken from the live site with a fresh
profile (a returning player is sent to the game) at a 1840×962 window — about
1.91:1, and the narrowest the whole hero fits in — at 2× for a sharp downscale.
The script letterboxes onto black rather than crop, so a source of another
shape keeps its edges. Like the home page's screenshots, it must not show the
chat. To retake it:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
  --hide-scrollbars --force-device-scale-factor=2 --window-size=1840,962 \
  --user-data-dir="$(mktemp -d)" --virtual-time-budget=5000 \
  --screenshot=static/og-source.png https://clickplanet.lol/
```

Chrome may not exit after it writes the file; stop it once the file is there.

`public/` holds the files that must be served as themselves rather than as the
app: `_headers`, `robots.txt`, `sitemap.xml` and `crazygames/words.txt` (fetched by the build and ignored by git,
see [CrazyGames](crazygames.md)). Vite copies them to the root of
`dist/`, and the Workers asset handler serves a real file before
`not_found_handling` applies — **without them, every unmatched path including
`/robots.txt` answers 200 with `index.html`**, so a crawler asking for the rules
got an HTML document. That was the leading suspect for LinkedIn refusing to
fetch the preview image, though it was never proven to be the only cause.
Nothing under `/static/` may be disallowed in robots.txt; that is where scrapers
fetch the preview from.

**`privacy.html` is the privacy policy**, linked from the home page and from the bottom of the About modal.
It is a plain page, not a component: it loads with no WebGL and no bundle, and a
crawler reads it as it is. The Workers asset handler serves it at `/privacy`
(`html_handling` drops the extension) and `nginx.conf` does the same with
`$uri.html`; `npm run dev` serves it at both `/privacy` and `/privacy.html`. **It states
retention periods, so it goes stale when the backend's do**: `ledger.retention`,
`antiBot.evidence.retention`, `chat.storage.retention`, `support.retention` and
`auth.sessions.guestTTL` in `deploy/vps/backend.yaml`, and `roll_keep_for` in
the Caddyfile. Change one, change the page and its date. **It names who keeps
the photos and videos of a note** (Cloudflare, for an R2 bucket): another
`support.attachments.bucket.endpoint` changes that line too.

**Its "Google user data" section is what Google's brand verification reads**:
what we ask Google for, why, that nobody else gets it, and the Limited Use
sentence. A new Google scope changes that section.

**Cloudflare Web Analytics counts the page views**, with no cookie. Each of the
five pages ends with the beacon tag, its token written once in
`src/webAnalytics.ts` and fed to the pages as `%WEB_ANALYTICS_TOKEN%`, like the
social profiles. The token is public. **`/auth/callback` has no beacon**: its URL
holds the one-time code, and its referrer is Google or Discord, which would read
as visitors sent from there. `gameRoutes` strips the tag from the copy and fails
the build if one is left. `"spa": false`, because the pages are real pages and
the home page's section links are not views. The site is a manual one (no
`auto_install`), so nothing is injected at the edge. No page sends a
Content-Security-Policy; one that is added must allow
`static.cloudflareinsights.com` (script) and `cloudflareinsights.com` (connect).

**`index.html` is the home page** and says what the game is in plain HTML — see
[Pages and routes](routes.md). It is a full landing page (header,
hero, how it works, the board and the map, phone, Discord, and a footer that
carries the creator) in the game's look, with one stylesheet inline and no
script but the redirect and `src/home.ts`, which fills the season, battle and Final Battle panels and keeps the
first landing. **It sells the game, not its mechanics**: country
against country on one live planet. What only makes sense once playing (signing
in to click faster, bonus boxes, the camera) stays in the game. The hero's
counts are written by hand, since plain HTML cannot read them: 262,000 tiles is
`earth-1`'s manifest's `tiles` (260,503), 239 flags is
`static/countries/countries.json`. Its screenshots are `static/home/*.jpg`,
taken from the live game at 1440×900 (390×844 for the phone) at 2× with a fresh
profile; a new one must not show the chat, which carries players' own words, and
a fresh profile opens it on a desktop, so fold it first. They are fixed names
under a week of cache, so a retake gets a new name. The section links (`#how`,
`#board`, `#creator`) work in the page, but a returning player who opens one
directly is sent to the game like any other hash but `#home`.

**The TikTok, YouTube and Instagram profiles are written once, in
`src/links.ts`.** About imports them; `vite.config.ts` hands them to the plain
pages, which write `%TIKTOK_PROFILE%`, `%YOUTUBE_CHANNEL%` and
`%INSTAGRAM_PROFILE%` (Vite's own HTML replacement, fed through `define`).
`links.test.ts` fails on one of them pasted into a page. **Discord has no
invite there**: the pages link `/play?discord=join`, the game's Discord sign-in
(see [Discord pings](discord-alerts.md)), and `links.test.ts` fails on a
`discord.gg` or `discord.com/invite` link in a page.

**`terms.html` is the terms of service**, linked beside it and built
the same way, at `/terms`. Discord asks for its URL to allow OAuth sign-in.
**`BannedModal` and `WarningModal` link its "Play fair" section** by its `id="play-fair"`, which
`BannedModal.test.tsx` pins: keep the id if the heading changes. The
privacy policy says what Google and Discord send us; a new provider, or a new
field kept from one, changes that page and its date.
