# Testing

Tests use `testify`. **A postgres store's own tests need Docker**, and so do `s3_attachment_bucket`'s, which start an S3 server (see [Support](support.md)), `cpoutbox`'s, and `cpredis`'s, which start a `redis:7.4-alpine` with `cpredis.StartTestServer(t)` (behind the tag; its `Config()` is the `redis` block to boot with, retrying every 50ms); nothing else does: a suite starts one `postgres:16-alpine` container in `SetupSuite` with `cppg.StartTestServer(t)` (behind the `testing` tag), opens and migrates its schema with `OpenSchema(t, schema, migrations.FS)`, and empties it in `SetupTest` with `Purge`. The container stops when the suite ends. There is no container shared across packages: `go test` runs each package as its own process, up to `-p` (GOMAXPROCS) at once. Everything above a store is tested against a fake of its port (`inmemory_tile_storage.MemoryPersistence`), so it runs without Docker.

**`e2e/` holds smoke tests, and nothing else.** They check that the main happy paths work and that the modules are wired together: the boot, the four listeners, the calls over the internal listener and the events over Redis. A rule, an edge case, a refusal or an error code is pinned lower down: a use case with fakes, a store's contract suite, a query's postgres suite or a handler test. Each lower test runs in milliseconds and names the rule it breaks; an e2e test costs a stack and says only that something, somewhere, went wrong. In October 2026 the package had grown to 107 tests that took six minutes of every `make test`; each was mapped to the lower tests that pin what it checked, the missing ones were written, and seven were kept; an eighth came with the rule sets.

`smoke_test.go` is one suite: `SetupSuite` boots every module once with `cpbootstrap.RunOn`, on one test postgres (`TestServer.ConfigFor(schema)`) and one test Redis (`cpredis.StartTestServer`, whose `Config()` goes in every module's `redis` block), with auth's fake providers and a fake bucket (`stack_test.go`). Every test plays on that stack with its own accounts, tiles and flags, so none reads what another wrote. `RunOn` serves on listeners the test already holds, bound to `127.0.0.1:0`: a port picked free and closed again can be taken by another process before the server binds it. Under `RunOn`, `cpbootstrap` binds nothing, and an address with no held listener fails the boot. The package runs in about 15 seconds.

- a guest clicks a tile, and the planet stream and `GetTileHolder` see it (planet asks auth for the key over the internal listener);
- seasons applies the rule set of its phase as planet's baseline (`ApplyRuleSet` over the internal listener), read back with `GetRules` on the console listener;
- the take reaches player's stats and seasons' `GetMySeason` over Redis, and the race, which seasons builds from planet's `GetTerritories`;
- a guest links Google over the fake provider, keeps its account, is given a name (`SignedIn` over Redis) and picks one (player asks auth whether the account is linked);
- a player posts, another reads the message under its name, and player counts it (`MessageSent`);
- a guest uploads a screenshot to the bucket and reports a bug, and the operator opens it from the console listener; three calls with no session before it spend none of the address's allowance, since the session check is the outer interceptor;
- a deleted account is forgotten by player, seasons, chat, support and planet (auth's outbox, then one `AccountDeleted` subscriber in each);
- an operator signs in on the admin listener and grants itself a bomb, which the game session alone cannot.

**A new smoke test is for a new module or a new path between modules**, never for a rule. It is a happy path, on the shared stack, and it reads only what it wrote. A test that needs another config, another clock or a second stack belongs lower down.

On macOS, testcontainers asks the Docker credential helper before it pulls an image, and that can hang with no prompt in a non-interactive shell. `docker pull postgres:16-alpine` and `docker pull redis:7.4-alpine` once from a terminal avoid it.

**Tests build with `-tags testing`, so use `make test` rather than a bare `go test ./...`.** Anything else that loads test files needs the tag too: `go vet -tags testing ./...`, and an editor's language server (`gopls` `buildFlags: ["-tags=testing"]`, or `go.buildTags` in VS Code), which otherwise reports the helpers as undefined. A helper that more than one package needs cannot live in a `_test.go` file, so it lives in an ordinary `.go` file carrying `//go:build testing`. The tag, not a filename convention, is what keeps such a helper out of the production binary — and what lets `make deadcode` tell a helper apart from production code. `cpctx.GetSessionID`, `cpconfigs.FromFile`, `cppg.StartTestServer`, `cpsession.TestKeyPair` (one fixed Ed25519 pair, so a test names both halves without carrying two magic strings), `cpredis.RecordedEvents` (the bus, for a use case that only publishes), `cpredis.StartTestServer` (a Redis for the bus), `cpatomic.FakeTransactioner` and `cpatomic.FakeOutbox` (a transaction and an outbox for a use case; see [Transactions](transactions.md)), `cpbootstrap.RunOn` (the boot, on listeners the test holds) and `cptime.FixedClock` — the stand-still clock a dozen test packages drive time with — are the shared ones.
