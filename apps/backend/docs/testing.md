# Testing

**Three levels, and nothing else.** An e2e smoke test (below) shows that the modules are wired. A use case's test,
over in-memory fakes, pins each rule. An adapter's test runs on the real thing, and a store's is the contract suite it
shares with its fake, so the fake stays true. So there is no test of a domain rule that a use case's test already
pins, of a handler or use case that passes an error on unchanged, of a fake outside its contract suite, or of a
migration's conversion of the rows: a migration runs once in production and never changes after, and every store
test runs all the migrations on an empty schema. November 2026 deleted about 350 tests that broke this rule.

Tests use `testify`. **A postgres store's own tests need Docker**, and so do `s3_attachment_bucket`'s and `cps3`'s, which start an S3 server (see [Support](support.md)), `cpoutbox`'s, and `cpredis`'s, which start a `redis:7.4-alpine` with `cpredis.StartTestServer(t)` (behind the tag; its `Config()` is the `redis` block to boot with, retrying every 50ms); nothing else does: a suite starts one `postgres:16-alpine` container in `SetupSuite` with `cppg.StartTestServer(t)` (behind the `testing` tag), opens and migrates its schema with `OpenSchema(t, schema, migrations.FS)`, and empties it in `SetupTest` with `Purge`. The container stops when the suite ends. There is no container shared across packages: `go test` runs each package as its own process, up to `-p` (GOMAXPROCS) at once. Everything above a store is tested against a fake of its port (`inmemory_tile_storage.MemoryPersistence`), so it runs without Docker.

**`e2e/` holds smoke tests, and nothing else.** They check that the main happy paths work and that the modules are wired together: the boot, the four listeners, the calls over the internal listener and the events over Redis. A rule, an edge case, a refusal or an error code is pinned lower down: a use case with fakes, a store's contract suite, a query's postgres suite or a handler test. Each lower test runs in milliseconds and names the rule it breaks; an e2e test costs a stack and says only that something, somewhere, went wrong. In October 2026 the package had grown to 107 tests that took six minutes of every `make test`; each was mapped to the lower tests that pin what it checked, the missing ones were written, and seven were kept. Each module or path between modules added since has one more.

`smoke_test.go` is one suite: `SetupSuite` boots every module but clips, alerts and publishing once with `cpbootstrap.RunOn`, on one test postgres (`TestServer.ConfigFor(schema)`) and one test Redis (`cpredis.StartTestServer`, whose `Config()` goes in every module's `redis` block), with auth's fake providers and a fake bucket (`stack_test.go`). Every test plays on that stack with its own accounts, tiles and flags, so none reads what another wrote. Before planet boots, the stack migrates its schema (`planet.Migrate`) and writes its own `clicks` into the rule set `default` (see [Rules](rules.md)), since every test clicks from one address. For the same reason, before the antibot boots, the stack migrates its schema (`antibot.Migrate`) and turns every watchdog off in its `default` set: a test's burst of clicks would get its player banned, sooner or later depending on the machine. Bans by hand still apply. `RunOn` serves on listeners the test already holds, bound to `127.0.0.1:0`: a port picked free and closed again can be taken by another process before the server binds it. Under `RunOn`, `cpbootstrap` binds nothing, and an address with no held listener fails the boot. **A helper that a test polls opens no pool**: the stack opens the pool it reads once, at boot (`gameStack.missions`, for `today`). Until November 2026, `today` opened a pool on each call, and `myTally` calls it in polls every 20 ms. Each pool kept its connection until the test ended, so a fast run used every connection of the test postgres (`too many clients already`), and the modules' own reads then failed: chat's `GetHistory` answered `internal` first. The package runs in about 15 seconds.

- a guest clicks a tile, and the planet stream and `GetTileHolder` see it (planet asks auth for the key over the internal listener);
- the take reaches progression's stats and scoring's `GetMyTally` over Redis, and a round's live standings, which scoring builds from planet's `GetTerritories`;
- a guest links Google over the fake provider, keeps its account, is given a name (`SignedIn` over Redis) and picks one (player asks auth whether the account is linked);
- a player posts, another reads the message under its name, and progression counts it (`MessageSent`);
- a guest uploads a screenshot to the bucket and reports a bug, and the operator opens it from the console listener; three calls with no session before it spend none of the address's allowance, since the session check is the outer interceptor;
- a guest does its flag's first mission and is paid once it signs in: missions draws the day from planet's map, hears the takes over Redis, asks player whether the account is signed in (`GetAccounts`), is told the sign-in (`PlayerSignedIn`, through player's outbox), and commands planet to grant the shields (`GrantCharges`, through its outbox);
- an account asked deleted is hidden from the other players at once and kept whole, then forgotten by player, progression, scoring, chat, support, missions, planet and the offers (a quiz answer it gave, written in their table since no quiz comes within a test) once the purge deletes it (`auth.deletion.grace` is 3s there; auth's outbox, then player's `AccountDeleted` subscriber, then player's outbox and one `PlayerForgotten` subscriber in each other module), and a sign-in within the grace period brings it back;
- an operator signs in on the admin listener and grants itself a bomb, which the game session alone cannot;
- an operator bans a guest's account on `antibot.v1`, and planet refuses its click with a `BanRefusal` once the command
  came through the antibot's outbox and Redis; an unban on `antibot.v1` admits it again (`refusal_test.go`);
- an operator adds a battle entry of the rule schedule on the console listener (the gamemaster module asks planet,
  the antibot and the offers which sets they keep), the three play its set once the gamemaster module called each
  (`PlayRuleSet`), scoring opens the battle's round, and the game client reads the battle's kind and its end on the public listener, as a GET and as the first
  event of the stream (`schedule_test.go`);
- a player reports a chat message, support tells `PlayerReported`, the chat's judge removes the message, and its
  outbox sends `DecideReport` back to support, which closes the report (`judge_test.go`);
- Claude connects with the operator's yes, lists the tools and calls one as the operator; a refusal is the tool's
  result (`connector_test.go`);
- an operator uploads a background and writes a set's cards, and a page reads the battle's teaser with the values the
  set plays and the points the battle gives (`promo_test.go`).

**One test there is not a smoke test and does not run by default**: `TestGiantEnclosuresOnTheWholeStack`
(`giant_enclosure_test.go`) is a measure, skipped unless `CP_GIANT_SCENARIOS` names the rings it plays; see
[Giant pockets, measured](enclose.md#giant-pockets-measured-2026-11-07).

**A new smoke test is for a new module or a new path between modules**, never for a rule. It is a happy path, on the shared stack, and it reads only what it wrote. A test that needs another config, another clock or a second stack belongs lower down.

On macOS, testcontainers asks the Docker credential helper before it pulls an image, and that can hang with no prompt in a non-interactive shell. `docker pull postgres:16-alpine` and `docker pull redis:7.4-alpine` once from a terminal avoid it.

**Tests build with `-tags testing`, so use `make test` rather than a bare `go test ./...`.** Anything else that loads test files needs the tag too: `go vet -tags testing ./...`, and an editor's language server (`gopls` `buildFlags: ["-tags=testing"]`, or `go.buildTags` in VS Code), which otherwise reports the helpers as undefined. A helper that more than one package needs cannot live in a `_test.go` file, so it lives in an ordinary `.go` file carrying `//go:build testing`. The tag, not a filename convention, is what keeps such a helper out of the production binary — and what lets `make deadcode` tell a helper apart from production code. `cpconfigs.FromFile`, `cppg.StartTestServer`, `cpsession.TestKeyPair` (one fixed Ed25519 pair, so a test names both halves without carrying two magic strings), `cpredis.RecordedEvents` (the bus, for a use case that only publishes), `cpredis.StartTestServer` (a Redis for the bus), `cpatomic.FakeTransactioner` and `cpatomic.FakeOutbox` (a transaction and an outbox for a use case; see [Transactions](transactions.md)), `refusals.MemoryStore` and `refusals.StoreContractSuite` (planet's refused callers), `cprules.MemoryStore` and `cprules.StoreContractSuite` (the rule sets of planet, the antibot and the offers; the suite runs on each module's migrations with that module's values), `rules.Seeded` (in each of the three: the set its migration keeps as `default`), `cprules.MemoryChoices` and `cprules.ChoiceStoreContractSuite` (the set the schedule chose), `schedule.FakeKeeper` and `schedule.FakeIDs` (the gamemaster module: a module that keeps some sets, and entry ids), `cpbootstrap.RunOn` (the boot, on listeners the test holds) and `cptime.FixedClock` — the stand-still clock a dozen test packages drive time with — are the shared ones.

**`make deadcode` fails on any unreachable function**, in two passes, because "is this reachable?" has two different right answers depending on whether test code counts as a caller. The first pass excludes tests and tagged files, so **production code whose only caller is a test is reported as dead** — the case a plain `deadcode -test` forgives. The second pass includes both but keeps only findings inside tagged files, so an unused shared helper is reported too. `deadcode` is fetched at a pinned version by the target, so there is nothing to install.
